## Summary

Overall score: **6/10.** The infrastructure is solid, but async error handling is inconsistent in the feature code, and that produces three critical, user-visible bugs.

| Severity | Count | Main themes |
| --- | --- | --- |
| Critical | 3 | Silent token refresh unmounts the app; false success after failed saves and deletes; drag-reorder corrupts saved order |
| Warning | 36 | Slice error and race handling, auth edge cases, error toast on signed-out startup, form state bugs, mouse-only controls, suppressed hook-deps lint, missing TS `lib` |
| Suggestion | \~20 | Duplicated template flows, no error boundary or code splitting, TypeScript escapes, test gaps |

- **Scope:** all of `src/` (303 TS/TSX files, about 18.5k lines), reviewed in four areas: `app` + `shared`, `entities`, `pages` and `components`. The stack is React 18.3, Redux Toolkit 2, react-router 6, react-hook-form, react-aria-components and oidc-client-ts, so no React 19 APIs are proposed.
- **Baseline:** `tsc --noEmit` and `yarn lint:ts` pass with no errors, and the unit tests pass (18 suites, 96 tests).
- **Since the review:** line coverage rose from 19% to 97% (96 suites, 608 tests). `yarn test:coverage` now fails below 90% lines/statements, 75% branches or 80% functions.
- **Root causes:** most criticals and warnings come from two patterns. The first is `await dispatch(thunk)` without `.unwrap()`. The second is reading a value assigned inside a `setState` updater. Lint does not catch either, and neither is covered by tests.
- **Verification:** every critical was re-checked against the source. Line numbers are as of commit `280b08d`.

## Critical issues (must fix)

Three defects lose user work or corrupt server data in normal use. All three were confirmed against the code.

### C1. A silent token refresh unmounts the whole app

`src/shared/auth/OidcAuthProvider.tsx:93` sets `isLoading` to `auth.isLoading || Boolean(auth.activeNavigator)`. react-oidc-context sets `activeNavigator` to `"signinSilent"` during `auth.signinSilent()`, which is what the session bridge's `refresh` calls (line 71). `src/app/routes/Router.tsx:119-123` then renders `<LoaderView/>` in place of `<BrowserRouter>`.

- **When it happens:** an API 401 (`shared/api/config/api.ts:80`) or a WebSocket close with code 4001 (`notificationClient.ts:71`), which occurs once per access-token lifetime.
- **Impact:** the route tree unmounts mid-wizard. Local `useFlow` state is lost, its cleanup resets the Redux slices, and the retried request resolves into unmounted components.
- **Fix (done):** the bridge's `refresh` now calls `userManager.signinSilent()` directly in place of `auth.signinSilent()`. react-oidc-context's wrapper dispatches `NAVIGATOR_INIT`, which sets **both** `activeNavigator` and `auth.isLoading`, so filtering `activeNavigator` alone would not have been enough. The direct call is the same path oidc-client-ts's `automaticSilentRenew` uses. The provider still receives the renewed user through the `userLoaded` event, and nothing flips the loader. The regression test `src/shared/auth/OidcAuthProvider.test.tsx` holds a renewal in flight and asserts `isLoading` stays `false`; it fails against the old code.

### C2. Saving a template reports success when the request fails

`components/Steps/FillCredentialData/FillCredentialData.tsx:63-100` and `components/Steps/RequestFieldsVerification/RequestFieldsVerification.tsx:84-122` call `await dispatch(createXTemplate(...))` without `.unwrap()`. A thunk rejected through `rejectWithValue` resolves normally, so it does not throw.

- **Impact:** on a 400, `handleError` shows an error toast. Then `SaveTemplateModal.tsx:48-51` also shows "created", closes the modal and navigates away, and the user's input is lost. Update shows `updateSuccess` unconditionally.
- **Same pattern elsewhere:** schema hide/show (`components/Schema/Schema.tsx:52-67`), Save on the from-template pages (`pages/IssueCredential/IssueFromTemplate/IssueFromTemplate.tsx:101-111`, `pages/VerifyCredential/VerificationFromTemplate/VerificationFromTemplate.tsx:102-112`, where the user sees an error toast and a success toast together), and template delete (`pages/IssueCredential/IssueTemplates/IssueTemplates.tsx:45-50`, `pages/VerifyCredential/VerificationTemplates/VerificationTemplates.tsx:43-51`).
- **Fix (done):** all nine call sites now `.unwrap()` the thunk. Create-from-wizard rethrows into `SaveTemplateModal`, whose `catch` keeps the modal open. Update, save, delete and schema-visibility handlers `catch` and return early. The thunk's `handleError` has already shown the error toast, so the success toast, navigation and `onVisibilityChanged` now run only on success. A sweep found no other `await dispatch(...)` followed by a success action without `.unwrap()`.

### C3. Drag-reordering while a search filter is active moves the wrong template

`components/Templates/Templates.tsx:92-103` takes `oldIndex`/`newIndex` from the dnd-kit sortable index, which is a position in `filteredTemplates` (line 166). It then applies `arrayMove` to the full `localTemplates` list.

- **Impact:** with two of ten templates visible, dragging between them reorders items 0 and 1 of the full list and sends the wrong `previousTemplateId` to the server, so the saved order is wrong.
- **Also:** `previousTemplateId` is assigned inside a `setState` updater and read right afterwards, so it can still be `undefined`. A failed request is not rolled back.
- **Fix (done):** `handleDragEnd` resolves both positions by id in the full list and computes the new order and `previousTemplateId` outside any `setState` updater. If the update fails, it restores the previous order. Supporting changes:
    - The page-level `changeTemplateOrder` callbacks now `.unwrap()`, so they reject on failure.
    - `previousTemplateId` is typed `string | null`, matching the backend DTO, where `null` means "move to top" and omitting it means "no reorder".
    - `src/components/Templates/Templates.test.tsx` covers the filtered drag, the unfiltered drag and the rollback. Against the old handler, the filtered test received `undefined` instead of `null`, and the rollback test failed.

## Suggestions (consider improving)

These reduce future bugs and duplication. None of them is broken today.

**Architecture and resilience**

- **No error boundary and no code splitting** (`app/routes/Router.tsx:9-19`). Every page is imported eagerly, and one render error blanks the app. Add a top-level error boundary and `React.lazy` + `Suspense` per page route. The `useMemo` around the routes at lines 112-115 does nothing useful.
- **Duplicated template flows.** `IssueFromTemplate` and `VerificationFromTemplate`, `AdvancedIssue` and `AdvancedVerification`, and `FillCredentialData` and `RequestFieldsVerification` each repeat the same fetch, hydrate and save logic. A `useTemplateFromLocation(kind)` hook, a `useTemplateSave(kind)` hook and a `TemplateActions` component would remove it, and would have prevented C2.
- **Fragile schema-sync effects** in `components/Steps/SelectSchema/SelectSchema.tsx:88-103`: two effects race to set the schema, and one calls `setSchema(undefined)` on an empty list. Replace them with one effect: `if (!schema && list.length) setSchema(singleSchema ?? list[0])`.
- **Long components:** `RegistrationView` chains 8 `setValue`/`resetField` effects that belong in the select `onChange` handlers, and `AgeVerificationDemo` packs three components into 311 lines.
- **Server state by hand.** Template, schema and connection lists hand-roll caching, invalidation and dedup. No thunk has a `condition` guard, so a double-click on `requestPresentation`, `offerCredential` or `createConnection` creates two server sessions. RTK Query fits the existing Redux stack, but it is optional.
- **Unneeded `memo` on the root component** (`app/App.tsx:9-23`). `App` takes no props and calls no hooks, and its only parent is `StoreProvider` (`index.tsx:17-21`), which renders once, so `memo` never skips a render. It also forces the `App.displayName = 'App'` line, because the wrapped arrow function has no name. Use `export const App = () => (...)` and delete the `displayName` line.
- **Dead code:** `DynamicModuleLoader`, `useAppState`, `buildSelector` and the `reducerManager` add/remove path are unused outside their own files and Storybook. All reducers are static.

**Correctness hardening**

- `presentation-request.ts:85-89` uses the schema name as an unescaped, unanchored regex, so `Test` also matches `TestSchema2`. Lines 54 and 302 build `$.${attribute}`, which is invalid JSONPath for names with spaces. Use `^escaped$` and `$['attr']`.
- Protocol switches in `presentation-request.ts` and `offerCredential.ts` have no `default` branch. Add an exhaustive `never` check.
- An unset `REACT_APP_AGENCY_ENDPOINT` becomes the string `"undefined"` (`api.ts:13`, `demoApi.ts:10`, `demoToken.ts:26`). Fail fast, as `OidcAuthProvider` already does.
- `api.ts:103-109` logs `error.response.data` in production, which can contain credential attributes. Gate it behind `__IS_DEV__`.

**TypeScript**

- `// @ts-ignore` at `IssueFromTemplate.tsx:160`. Non-null assertions in `AdvancedIssue.tsx:114-117` (crashes with no schema), `IssueTemplates.tsx`, `FillCredentialData.tsx:68-72` and `RequestFieldsVerification.tsx:89-93`. Deep imports from `react-hook-form/dist/types/...` in `CredentialField.tsx:4` and `TextInput.tsx:4`.
- `updateCredentialState.ts:17-19` types the result as `OpenIdIssuanceState`, but the Aries path returns `AnoncredsCredentialState`.

**Accessibility and i18n**

- The QR code (`components/QRCode/QRCode.tsx:15`) has no text alternative. Pass `title` and `aria-label`.
- `Loader` has no `role="status"`. The modal close buttons (`shared/ui/Modal/Modal.tsx:32,42`) and logo `alt` texts are hardcoded English.

**Tests**

- Tests cover only `Connection`, `Presentation`, auth and a few shared utilities. There are no tests for the template, schema, credential or user slices, the `credential.ts` builders, `offerCredential`, or the `toDcApiError` mapping. There are no component tests for the template or reorder flows where C2 and C3 live.

## Positive observations

The auth, real-time and DC API layers are well built and should be the model for the rest of the app.

- **Auth:** Authorization Code + PKCE through oidc-client-ts, tokens in `sessionStorage`, and `code`/`state` cleared from the URL after the callback. No `dangerouslySetInnerHTML` anywhere.
- **WebSocket client:** the token goes in `Sec-WebSocket-Protocol`, not the URL. It has exponential backoff, a stale-socket guard, and a connect/disconnect lifecycle tied to sign-in.
- **`useRecordUpdates`:** uses `useSyncExternalStore` for socket status and a ref for `refresh`, does a catch-up fetch on open, falls back to polling, and cleans up every effect.
- **`connectionSlice`:** guards stale updates with an `isExisting` lock and a `meta.arg.id` check, and its tests cover those races. W3 should copy this pattern.
- **DC API flow:** a typed `DcApiError` with stable codes, `AbortSignal` passed through to `navigator.credentials.get`, and `rejected.match` to separate cancelled, unsupported and failed.
- **Thunks:** API clients are injected through `extra`, which makes the tenant-switch tests simple. Selectors return stored references, so `createSelector` is not needed.
- **dnd-kit in `CredentialFields`:** `field.id` serves as both the sortable id and the key. Elsewhere, list keys are stable ids.
- **Tooling:** `tsc --noEmit` and `yarn lint:ts` pass clean, and all 18 suites (96 tests) pass.

   ```ts
   // shared/lib/store/runThunk.ts
   export async function runThunk<T>(
     p: { unwrap(): Promise<T> },
     onSuccess: (v: T) => void,
   ) {
     try {
       onSuccess(await p.unwrap());
     } catch {
       // handleError already showed the error toast
     }
   }
   
   // call site
   await runThunk(dispatch(deleteVerificationTemplate({ templateId })), () =>
     toast.success(t('Template.messages.deleted')),
   );
   ```
